# stonewards-mod-settings

stonewards-mod-settings is one shared settings menu inside Stonewards for all mods. Any mod can register its options, such as toggles, sliders, dropdowns and text fields, with default values. Players change them in the game without editing config files, and the changes are saved and passed back to the mod they belong to. It follows the conventions of the sibling stonewards-upgrade-queue mod, which will be the first mod to use it.

## How it works

- `Patches/MainMenuPatches.cs` adds a **Mod Settings** button to the title screen in the empty slot above Roadmap, placed from the neighbouring buttons' laid-out positions.
- `Patches/PauseMenuPatches.cs` adds a **Mods** button after the game's Settings button in `UIPauseMenu` and puts the panel in the same UI document, copying the settings screen's style sheets. Escape closes the panel (or cancels a key rebind) before the pause menu sees it, and the pause box grows to fit the extra button.
- `Theme.cs` restyles the panel and Unity's built-in control parts to the game's grey and gold menus.
- `SettingsRegistry.cs` lists the settings of every plugin in `Chainloader.PluginInfos` each time the panel opens: its `Config` plus any other `ConfigFile` fields on the plugin class. Optional ConfigurationManager-style tags refine how settings are shown; see `thunderstore/README.md`.
- `SettingEditors.cs` picks a control per setting type and writes through `ConfigEntryBase.BoxedValue`, so mods get their usual `SettingChanged` events immediately. `ConfigWriter` batches file saves (every second while open, and on close) so sliders don't rewrite the file on every step.

## Development

Requires the .NET SDK, Stonewards, and an r2modman profile with BepInExPack 5.4.2305 installed.

- `dotnet build src/ModSettings/ModSettings.csproj` builds the plugin and copies it into the r2modman profile's `BepInEx/plugins/darkharasho-ModSettings`.
- `scripts/package.sh` builds Release and writes a Thunderstore zip to `dist/`. It fails if the versions in `thunderstore/manifest.json`, `Plugin.cs` and the `.csproj` differ, or if `CHANGELOG.md` has no entry for that version. The package uses `thunderstore/README.md` (the store page), not this file.
- `thunderstore/icon.svg` is the icon source. Regenerate the PNG with `rsvg-convert -w 256 -h 256 thunderstore/icon.svg -o thunderstore/icon.png`.

### Releases

Pushing a `v*` tag runs `.github/workflows/release.yml`. It checks the tag matches `thunderstore/manifest.json`, runs `scripts/package.sh`, and creates a GitHub release with the zip and that version's changelog entry, then publishes the zip to Thunderstore with `scripts/thunderstore-publish.sh` (using the `THUNDERSTORE_TOKEN` repo secret; versions already on Thunderstore are skipped). Bump the version in the manifest, `Plugin.cs`, the `.csproj` and `CHANGELOG.md` first, then `git tag vX.Y.Z && git push origin vX.Y.Z`.

CI has no game install, so it builds against `lib/refs`: reference-only assemblies (public signatures, no code) generated by `scripts/update-refs.sh`. Local builds use the real game DLLs when they exist; pass `-p:UseRefs=true` to test the CI setup. Rerun `scripts/update-refs.sh` after a game update that changes APIs the mod uses, or when adding a `<Reference>`.

### Paths

Game and profile paths default to this dev machine. Override them with `-p:GamePath=... -p:ProfilePath=...` or a gitignored `Local.props`:

```xml
<Project>
  <PropertyGroup>
    <GamePath>C:\Program Files (x86)\Steam\steamapps\common\Stonewards</GamePath>
    <ProfilePath>C:\Users\you\AppData\Roaming\r2modmanPlus-local\Stonewards\profiles\Default</ProfilePath>
  </PropertyGroup>
</Project>
```
